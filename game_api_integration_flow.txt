2.1. NGƯỜI DÙNG XEM DANH SÁCH TRÒ CHƠI
--------------------------------------
Frontend → Backend → Database → Frontend

[Frontend: wap/src/views/games/GamesHome.vue]
  ↓ HTTP GET Request
  ↓ Endpoint: /api/games/list
  ↓
[Backend: boyue/app/controller/api/GamesController.php]
  ↓ Query Database
  ↓ SELECT * FROM games WHERE status = 1
  ↓
[Database: games table]
  ↓ Return game list
  ↓
[Backend: Format response JSON]
  ↓ Response: {code: 0, data: [...games], msg: "success"}
  ↓
[Frontend: Display games in GameCard.vue]

Dữ liệu trả về:
- game_id: ID trò chơi
- game_name: Tên trò chơi
- game_code: Mã trò chơi
- provider: Nhà cung cấp (PG, TCG, etc.)
- game_type: Loại game (slot, live, sports)
- thumbnail: Hình ảnh game
- status: Trạng thái (1=active, 0=inactive)

2.2. NGƯỜI DÙNG KHỞI CHẠY TRÒ CHƠI
----------------------------------
Frontend → Backend → Game Provider API → Backend → Frontend

[Frontend: User clicks game]
  ↓ HTTP POST Request
  ↓ Endpoint: /api/games/launch
  ↓ Payload: {game_id, user_token}
  ↓
[Backend: GamesController::launch()]
  ↓ Validate user session
  ↓ Check user balance
  ↓ Get game configuration
  ↓
[Backend: Call Game Provider API]
  ↓ HTTP POST to Provider
  ↓ Endpoint: https://provider.com/api/game/launch
  ↓ Payload: {
  ↓   operator_id: "xxx",
  ↓   player_id: "user_123",
  ↓   game_code: "pg_slot_001",
  ↓   currency: "VND",
  ↓   language: "vi",
  ↓   return_url: "https://site.com/games"
  ↓ }
  ↓
[Game Provider API]
  ↓ Validate credentials
  ↓ Generate game session
  ↓ Return game URL
  ↓ Response: {
  ↓   status: "success",
  ↓   game_url: "https://provider.com/game/session_token",
  ↓   session_id: "sess_xyz"
  ↓ }
  ↓
[Backend: Save session to database]
  ↓ INSERT INTO game_sessions (user_id, game_id, session_id, provider)
  ↓
[Backend: Return game URL to frontend]
  ↓ Response: {code: 0, data: {game_url: "..."}, msg: "success"}
  ↓
[Frontend: Open game in iframe/new window]

2.3. NGƯỜI DÙNG CHƠI GAME - CALLBACK TỪ PROVIDER
------------------------------------------------
Game Provider → Backend → Database → Game Provider

[Game Provider: Player places bet]
  ↓ HTTP POST Callback
  ↓ Endpoint: /api/games/callback/bet
  ↓ Payload: {
  ↓   operator_id: "xxx",
  ↓   player_id: "user_123",
  ↓   game_round_id: "round_456",
  ↓   bet_amount: 10000,
  ↓   currency: "VND",
  ↓   timestamp: "2026-05-31T21:00:00Z",
  ↓   signature: "hash_signature"
  ↓ }
  ↓
[Backend: GamesController::callbackBet()]
  ↓ Verify signature
  ↓ Validate player exists
  ↓ Check sufficient balance
  ↓
[Backend: Deduct balance]
  ↓ BEGIN TRANSACTION
  ↓ UPDATE users SET balance = balance - 10000 WHERE id = user_123
  ↓ INSERT INTO game_transactions (user_id, type='bet', amount, game_round_id)
  ↓ COMMIT
  ↓
[Backend: Return response to provider]
  ↓ Response: {
  ↓   status: "success",
  ↓   balance: 990000,
  ↓   transaction_id: "txn_789"
  ↓ }
  ↓
[Game Provider: Continue game]

[Game Provider: Game result - Win/Lose]
  ↓ HTTP POST Callback
  ↓ Endpoint: /api/games/callback/result
  ↓ Payload: {
  ↓   operator_id: "xxx",
  ↓   player_id: "user_123",
  ↓   game_round_id: "round_456",
  ↓   win_amount: 25000,
  ↓   currency: "VND",
  ↓   timestamp: "2026-05-31T21:01:00Z",
  ↓   signature: "hash_signature"
  ↓ }
  ↓
[Backend: GamesController::callbackResult()]
  ↓ Verify signature
  ↓ Check round not already settled
  ↓
[Backend: Add winnings]
  ↓ BEGIN TRANSACTION
  ↓ UPDATE users SET balance = balance + 25000 WHERE id = user_123
  ↓ INSERT INTO game_transactions (user_id, type='win', amount, game_round_id)
  ↓ UPDATE game_rounds SET status='settled', win_amount=25000
  ↓ COMMIT
  ↓
[Backend: Return response]
  ↓ Response: {
  ↓   status: "success",
  ↓   balance: 1015000,
  ↓   transaction_id: "txn_790"
  ↓ }

  ↓ SELECT
  ↓   g.game_name,
  ↓   gp.name as provider_name,
  ↓   COUNT(DISTINCT gt.user_id) as total_players,
  ↓   COUNT(gt.id) as total_rounds,

  ↓   SUM(CASE WHEN gt.type='win' THEN gt.amount ELSE 0 END) as total_wins,

  ↓ JOIN games g ON gt.game_id = g.id
  ↓ JOIN game_providers gp ON g.provider_id = gp.id
  ↓ WHERE gt.created_at BETWEEN ? AND ?

5. CẤU TRÚC DATABASE (DATABASE SCHEMA)
================================================================================

Table: game_providers
---------------------
id                INT PRIMARY KEY AUTO_INCREMENT
name              VARCHAR(100)      -- Provider name
code              VARCHAR(20) UNIQUE -- Provider code (PG, TCG, etc.)
api_url           VARCHAR(255)      -- API endpoint URL
api_key           VARCHAR(255)      -- API key (encrypted)
api_secret        VARCHAR(255)      -- API secret (encrypted)
operator_id       VARCHAR(100)      -- Operator ID
currency          VARCHAR(10)       -- Default currency (VND, USD)
language          VARCHAR(10)       -- Default language (vi, en)
callback_url      VARCHAR(255)      -- Callback URL for provider
webhook_secret    VARCHAR(255)      -- Webhook signature secret
status            TINYINT           -- 0=inactive, 1=active
created_at        DATETIME
updated_at        DATETIME

Table: games
------------
id                INT PRIMARY KEY AUTO_INCREMENT
provider_id       INT               -- FK to game_providers
game_code         VARCHAR(50)       -- Provider's game code
game_name         VARCHAR(200)      -- Game display name
game_type         VARCHAR(20)       -- slot, live, sports, etc.
thumbnail         VARCHAR(255)      -- Game image URL
rtp               DECIMAL(5,2)      -- Return to player %
volatility        VARCHAR(20)       -- low, medium, high
max_win           INT               -- Maximum win multiplier
status            TINYINT           -- 0=inactive, 1=active
sort_order        INT               -- Display order
created_at        DATETIME
updated_at        DATETIME
INDEX idx_provider (provider_id)
INDEX idx_type (game_type)
INDEX idx_status (status)

Table: game_sessions
--------------------
id                INT PRIMARY KEY AUTO_INCREMENT
user_id           INT               -- FK to users
game_id           INT               -- FK to games
provider_id       INT               -- FK to game_providers
session_id        VARCHAR(100)      -- Provider's session ID
game_url          TEXT              -- Game launch URL
status            VARCHAR(20)       -- active, completed, expired
created_at        DATETIME
expired_at        DATETIME
INDEX idx_user (user_id)
INDEX idx_session (session_id)

Table: game_transactions
------------------------
id                BIGINT PRIMARY KEY AUTO_INCREMENT
user_id           INT               -- FK to users
game_id           INT               -- FK to games
provider_id       INT               -- FK to game_providers
game_round_id     VARCHAR(100)      -- Provider's round ID
transaction_type  VARCHAR(20)       -- bet, win, refund
amount            DECIMAL(15,2)     -- Transaction amount
balance_before    DECIMAL(15,2)     -- Balance before transaction
balance_after     DECIMAL(15,2)     -- Balance after transaction
status            VARCHAR(20)       -- pending, completed, failed
provider_txn_id   VARCHAR(100)      -- Provider's transaction ID
created_at        DATETIME
INDEX idx_user (user_id)
INDEX idx_game (game_id)
INDEX idx_round (game_round_id)
INDEX idx_created (created_at)

Table: game_rounds
------------------
id                BIGINT PRIMARY KEY AUTO_INCREMENT
user_id           INT               -- FK to users
game_id           INT               -- FK to games
provider_id       INT               -- FK to game_providers
round_id          VARCHAR(100) UNIQUE -- Provider's round ID
bet_amount        DECIMAL(15,2)     -- Total bet amount
win_amount        DECIMAL(15,2)     -- Total win amount
status            VARCHAR(20)       -- active, settled, cancelled
started_at        DATETIME
settled_at        DATETIME
INDEX idx_user (user_id)
INDEX idx_round (round_id)
INDEX idx_status (status)

7. BẢO MẬT VÀ XÁC THỰC (SECURITY & AUTHENTICATION)
================================================================================

7.1. USER AUTHENTICATION
------------------------
- JWT token in Authorization header
- Token expiry: 24 hours
- Refresh token mechanism
- Session validation on each request

7.2. ADMIN AUTHENTICATION
-------------------------
- Separate admin JWT token
- Role-based access control (RBAC)
- Permission checking per endpoint
- Admin activity logging

7.3. PROVIDER API SECURITY
--------------------------
- API Key + Secret authentication
- Request signature verification (HMAC-SHA256)
- Timestamp validation (prevent replay attacks)
- IP whitelist (optional)
- SSL/TLS encryption (HTTPS only)

Signature Generation Example:
-----------------------------
string_to_sign = method + url + timestamp + body
signature = HMAC_SHA256(string_to_sign, api_secret)
headers = {
  "X-API-Key": api_key,
  "X-Timestamp": timestamp,
  "X-Signature": signature
}

7.4. CALLBACK VERIFICATION
--------------------------
- Verify webhook signature from provider
- Validate request origin
- Check timestamp freshness
- Prevent duplicate processing (idempotency)

-----------------
- Cache provider configurations (Redis)
- Cache game lists (Redis, 1 hour TTL)

- Implement request queuing for high load
- Optimize database queries with indexes
- Use CDN for game thumbnails

-----------------

- Use circuit breaker pattern
- Implement fallback mechanisms
- Transaction atomicity (database transactions)
- Idempotency for callbacks
- Regular health checks

11.3. SCALABILITY
-----------------
- Horizontal scaling for API servers
- Load balancing across servers
- Database read replicas
- Redis cluster for caching
- Async processing for non-critical tasks
- Message queue for callbacks
